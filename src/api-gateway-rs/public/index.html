Custom actions

Register any endpoint — not just the built-in services — so your agents can call it too, with the same dedup, audit, and rate-limit protection. You approve the URL here; agents only ever invoke it by name afterward.

One per line: Header-Name: value. Prefix the value with secret: to encrypt it at rest (e.g. a signing key) instead of storing it in the clear.

Comma-separated. Each gets a best-effort copy of the same payload after the primary call succeeds — doesn't affect the response or block on failure.

Registered actions

MCP servers

Register any third-party MCP server (Notion, GitHub, or anything from the open MCP ecosystem) and every tool it exposes gets AgentRaaS's dedup, circuit breaker, and audit protection automatically — no per-tool setup. Its tools show up in tools/list as <name>.<tool>.

Registered servers

Validation rules

Define required fields, types, and constraints for any service.action — including Custom Actions, which otherwise have no validation at all. A rule you save here always overrides a curated service's built-in rule for that same action.

Saved rules

Dedup rules

By default AgentRaaS dedupes on the whole request payload — two calls only count as the same request if they're byte-identical. Configure a rule here to instead dedupe on one or more specific fields (e.g. customer_email), so "same email = duplicate" regardless of what else differs in the payload. An explicit X-AgentRaaS-Idempotency-Key header on a call always takes precedence over any rule configured here.

Comma-separated top-level payload field names. Up to 10.

Saved rules

Tool output pruning

Strips HTML tags, drops null/empty fields, truncates strings over 2000 characters, and caps arrays at 50 items on every tool response before it reaches the model — cuts token costs on verbose upstream JSON/HTML. Off by default.

Human-in-the-loop approval rules

Team-tier and above. A request matching a rule below is frozen and sent to Slack for Approve/Deny before it forwards. Leave field/operator/threshold blank to always require approval for that service.action, or set them to only freeze when a payload field crosses a threshold (e.g. amount greater than 10000). Webhook calls only. Configure the Slack destination with your AgentRaaS contact.

Saved rules

Action policies

What an agent is allowed to do. "Never allow" blocks a service.action outright (use * as the action for every action of a service). "Only allow when" lets a call through only if its payload passes the limits, written like a validation rule; domains restricts an email or URL field to your own domains. Every matching policy applies. Leave Agent ID blank for every agent in the org.

Saved policies

Per-agent spend caps

Caps how many times an agent can call a service.action within a time window — catches an agent that's legitimately busy (not looping) but burning through a paid API faster than expected. Leave Agent ID blank to apply to every agent in the org. "Route to approval" needs a configured HITL Slack destination; otherwise the call is rejected outright once the cap is hit.

Saved rules

Local dev tunnel

Receive a real inbound webhook (Stripe, WhatsApp, etc.) on your local machine while you build — open a tunnel from your terminal with node infra/scripts/tunnel-cli/index.js --port <local-port> --org <org_id> --agent <agent_id> --key <api_key>, then watch requests here as they arrive. One active tunnel per org; it auto-expires after 2 hours.

Saved targets

Instant outage alerts

Get pinged in Slack, Discord, or Telegram the moment AgentRaaS's circuit breaker shields your org from an unresponsive service — rate-limited to one alert per service per minute, so a burst of blocked requests doesn't spam you.

Configured alerts

Failed requests

Requests where the target API itself returned an error — not ones blocked by AgentRaaS (validation, usage limits, an already-open circuit). Review the payload, edit it if needed, and replay once the underlying issue is fixed.

Recordings

Calls your agents made with X-AgentRaaS-Record: <name>, kept for 30 days. Replay one with X-AgentRaaS-Replay: <name>: each call is answered from the recording and nothing reaches the provider. See Record and replay.

Undo actions

Actions your agents ran that AgentRaaS knows how to reverse, for 30 days: a Stripe charge is refunded, a Slack message deleted, a custom action reversed by the action you named. Each one can be undone once. Actions without a known reverse (an SMS, an email) don't appear here.

Reliability report

Uses the same date range as the dashboard's own 24h/7d/30d/90d selector. Uptime is shared across every org calling a service (one circuit breaker per service, not per org); success rate and duplicates prevented are scoped to your own orgs.

Opt-in only. Enabling this makes a real, read-only request to the service every 5 minutes using your own stored credentials, to catch a dead key or outage before an agent's real request does. Only available for services with a well-established safe check endpoint.
