2 · FIX @exactly_once
agent.py
from agentraas.local import exactly_once

@exactly_once()  # SQLite by default, or RedisStore
def charge(customer, amount, idempotency_key=None):
    return stripe.Charge.create(
        customer=customer, amount=amount,
        idempotency_key=idempotency_key,  # same on every retry
    ).id

charge("cus_1", 4200)  # runs
charge("cus_1", 4200)  # cached, no second charge

Retries, concurrent duplicates and lost responses covered. Python today; TypeScript coming.

The problem

Your agent didn't fail. The network did, and nobody told it.

Your n8n workflow hits Stripe. It times out. n8n retries.

The customer is charged twice, and you find out from a support ticket, not a log.

CRM duplicate

Two duplicate contacts, a messier pipeline, and a sales team that stops trusting the data.

The client gets the same update twice, and starts wondering what else is off.

Team notification

Your team approves the same request twice, or gets paged twice for one incident.

How it works

A dedup slot claimed atomically, before anything real happens.

01

Your agent sends the request to AgentRaaS instead of the API directly.

02

AgentRaaS atomically claims a dedup slot for that exact request in Redis.

03

First call: forwarded to the real API, and the result is cached.

04

Retry or duplicate: the cached result comes back. Never a second real execution.

Why not DIY idempotency keys?

Calling Stripe by hand? Its Idempotency-Key header is genuinely enough.

The honest case for AgentRaaS is narrower: not every provider has native idempotency (Twilio, Slack, most CRMs and your own endpoints don't), no-code tools can't set the header at all, and none of them give you one audit trail across services.

When AgentRaaS is down

Fail-closed by design, not fail-silent.

AgentRaaS sits in the request path. If it's unreachable, your call fails; it never silently succeeds un-deduped. There is no fallback anywhere in the SDK, the n8n node or the MCP gateway that quietly calls Stripe or Twilio directly. Routing around an outage would mean the exact retry-storm double charge this product exists to prevent, at the moment you'd least want it. Treat it like any other dependency on your critical path.

FAQ

Questions people actually ask

The short, honest answers. Full detail is in the docs and LICENSE.md.

Is self-hosted really unlimited, on every tier?

Yes. Community, Team, and Enterprise are all unlimited actions/month when you run them on your own infrastructure: no cap, no metering, no phone-home check. It's a term of LICENSE.md, not a "soft" limit we quietly enforce. The only metered tier is the free AgentRaaS Cloud account (500 actions/month), because that one runs on our infrastructure, not yours. Team/Enterprise features on a self-hosted instance unlock via a license token you paste into your own .env once at setup, verified entirely offline, with no network call back to us.

What's the difference between Team and Enterprise?

Team ($49/mo) is for an individual builder or small team past the free tier's usage cap: 3 seats and the Human-in-the-Loop approval gateway with SLA auto-escalation. Enterprise (custom pricing) adds everything needed for a production multi-team deployment or an agency managing multiple client workspaces: unlimited seats, unlimited client tenants with white-label branding, inbound webhook receivers, active-active HA clustering, PII/DLP redaction, and OIDC SSO with RBAC. Both run cloud-hosted or self-hosted.

Is my data safe if I self-host?

Self-hosted means your audit log, credentials, and traffic never leave infrastructure you control. We don't see any of it. Stored credentials are encrypted at rest (AES-256-GCM), and the Enterprise tier adds PII/DLP redaction before anything touches the audit log, plus tamper-evident, SIEM-exportable logging for compliance-sensitive teams.

Do you support n8n, Make, or Zapier?

Yes. No-code tools work the same way code does: point the HTTP Request node at your AgentRaaS URL instead of the API directly. No custom node install required for any of them.

What happens if my agent retries a request?

AgentRaaS claims an atomic dedup slot in Redis before anything real happens. The first call gets forwarded and its result cached; any retry or duplicate, even a concurrent one, gets the cached result back instead of a second real execution. This is tested under real concurrent load, not just claimed (see src/api-gateway-rs/test/dedup.test.js).

Is this open source?

The core engine (src/api-gateway-rs/crates/core/: payload dedup, MCP gateway, dashboard) is MIT/Apache-2.0. Enterprise features (src/api-gateway-rs/crates/api/src/ee/: SSO, HMAC, DLP, distributed rate limiting) are source-available under a separate commercial license. See LICENSE.md for the exact terms.

What does "agentgateway-compatible" mean?

agentgateway (a Linux Foundation project) is an edge proxy for AI traffic: auth, RBAC, rate limiting, and observability across all your MCP/tool servers, not just AgentRaaS. If you already run it (or want to), AgentRaaS drops in as a backend behind it with zero code changes on either side. See Getting started for the one-command setup. Most self-hosters don't need this; it matters once you're managing more than one MCP server behind a shared gateway.
