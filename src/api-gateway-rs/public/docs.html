Documentation

Everything you need to wire an agent through AgentRaaS: authentication, the two calling styles, MCP, SDKs, and self-hosting reference.

AgentRaaS sits between your agent and the real API it's calling (Stripe, Twilio, your own internal endpoint, anything). It claims an atomic dedup slot before forwarding anything, so a retry from your agent, your framework, or a flaky network never becomes a second real charge, message, or side effect. Every call is logged with a per-agent identity for a full audit trail.

New to AgentRaaS? Start with Getting started for the click-by-click walkthrough of connecting your first agent. This page is the reference once you're wiring things up for real.

Quickstart

  1. Register and log in at the dashboard (Cloud), or self-host with ./install.sh. See Self-hosting below.
  2. Click + Connect agent. You get an API key, a webhook URL, and an MCP URL, shown once. Save the API key; it can't be retrieved again.
  3. Add credentials for whatever service you're calling (Credentials panel); AgentRaaS forwards using those, so your agent code never touches a raw upstream API key.
  4. Call AgentRaaS instead of the real API, using either calling style below.

Library mode Free

Exactly-once execution with no AgentRaaS server at all. Decorate any function that has a side effect; retries and concurrent duplicates get the first result back instead of running it again. State lives in a local SQLite file by default, or in your own Redis.

pip install agentraas
from agentraas.local import exactly_once, RedisStore

@exactly_once()                      # SQLite file, one machine
def charge(customer, amount, idempotency_key=None):
    return stripe.Charge.create(customer=customer, amount=amount,
                                idempotency_key=idempotency_key).id

charge("cus_1", 4200)   # runs for real
charge("cus_1", 4200)   # returns the cached id, no second charge

@exactly_once(store=RedisStore("redis://localhost:6379/0"),   # across machines
              key=lambda order: order["id"], ttl=3600)
async def ship(order):
    ...
OptionDefaultWhat it does
storeSQLite fileSQLiteStore(path) for one machine, RedisStore(url) for several (needs pip install redis).
keyall argumentsFunction returning what counts as "the same call", e.g. an order ID.
ttl86400Seconds a completed result is remembered.
wait30Seconds a duplicate waits for an in-flight first call before raising InFlightError.

If the function raises, nothing is cached and a retry runs it again. That includes the case where the provider did the work but the response was lost. Give the function an idempotency_key parameter and pass it to the provider: the decorator fills it with the same value on every retry, so the provider dedupes that case itself. Results must be JSON-serializable.

MCP wrap Free

Exactly-once tool calls and an audit log for any stdio MCP server. Put agentraas wrap -- in front of the server's own command; everything passes through unchanged, except that an identical call to a write tool (same tool, same arguments) inside the dedup window gets the first call's result back instead of running again.

{
  "mcpServers": {
    "github": {
      "command": "uvx",
      "args": ["agentraas", "wrap", "--", "npx", "-y", "@modelcontextprotocol/server-github"]
    }
  }
}
OptionDefaultWhat it does
--ttl600Seconds an identical write call is deduplicated.
--dedupe TOOLAlways dedupe this tool, even if it looks read-only. Repeatable.
--no-dedupe TOOLNever dedupe this tool. Repeatable.
--db~/.agentraas/mcp-dedup.dbSQLite file for dedup state.
--log~/.agentraas/mcp-audit.jsonlJSON-lines audit log of every tool call; '' disables it.

Read-only tools always run, so lookups stay fresh: the server's readOnlyHint annotation decides, falling back to names like get_*, list_* and search_*. A failed call (JSON-RPC error or isError: true) is not cached, so a retry runs for real. A deduplicated result carries _meta: {"agentraas/deduplicated": true}.

Chaos tester Free

agentraas-chaos sits between your code and an API. The first time each distinct write request (POST, PUT, PATCH, DELETE) arrives, it lets the request execute and then drops the response: the network failure that turns a retry into a double charge. It then lists every action that executed more than once.

# safe: a built-in mock answers every call
agentraas-chaos --mock -- python my_agent.py

# a real API: use test-mode keys
agentraas-chaos --upstream https://api.stripe.com -- pytest

Your command gets AGENTRAAS_CHAOS_URL (for example http://127.0.0.1:8787) to use as its API base URL. Without a command it runs until Ctrl-C, so you can point an n8n workflow or any other tool at it by hand. It exits with code 1 when it finds a duplicate. A retry that repeats an Idempotency-Key it has already seen counts as protected.

FlagWhat it does
--mockAnswer every call with a fake 200. Nothing real is called.
--upstream URLForward to a real API base URL.
--faultlost-response (default) drops the connection; error-after-commit returns a 502 instead; none only records.
--portLocal port, default 8787.

GitHub Actions

- uses: actions/setup-python@v5
  with: { python-version: "3.12" }
- uses: sumedhchatse/agentraas/src/chaos-action@main
  with:
    run: python my_agent.py      # optional: upstream, fault

Authentication

Every route accepts your API key in a different place depending on the calling style you use; there's no single global header. Keys start with ar_live_ and are shown exactly once when you connect an agent; AgentRaaS only ever stores a hash of it.

Calling styleWhere the key goes
WebhookAuthorization: Bearer <key>
SDK-style RESTx-agentraas-key: <key> header
MCPx-agentraas-key: <key> header

Lost a key? Connect a new agent and revoke the old one from the Credentials panel; there's no way to have a lost key re-displayed.

REST: webhook style

The simplest integration: point any no-code tool (n8n, Make, Zapier) or a plain curl/HTTP client at one URL per agent. org_id and agent_id live in the path, so nothing else needs configuring per request.

POST /v1/webhook/:org_id/:agent_id
curl -X POST https://your-instance/v1/webhook/acme-corp/billing-bot \
  -H "Authorization: Bearer ar_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "service": "stripe",
    "action": "charge.create",
    "payload": { "amount": 5000, "currency": "usd", "customer": "cus_123" }
  }'
FieldRequiredDescription
serviceYesWhich connector. See Supported services, or a Custom Action's name.
actionYesWhich operation on that service.
payloadNoFields the action needs, matching the real API's own shape.
end_user_idNoYour own identifier for who this action was on behalf of. Shows up in the audit trail.
resource_idNoYour own identifier for what was acted on (an order id, a ticket id, etc.).

A successful response, first call vs. a retry of the same request:

→ 200 OK   // first call, forwarded, result cached
{"result":{"status":"success","charge_id":"ch_1N..."}}

→ 200 OK   // identical retry, dedup slot already claimed
{"result":{"status":"success","charge_id":"ch_1N...","deduplicated":true}}

REST: SDK style

Used by the official SDKs (see SDKs): org_id/agent_id travel as headers instead of the URL, so one client instance can be reused across calls without rebuilding a path each time.

POST /v1/sdk/:service/:action
curl -X POST https://your-instance/v1/sdk/stripe/charge.create \
  -H "x-agentraas-key: ar_live_..." \
  -H "x-agentraas-org: acme-corp" \
  -H "x-agentraas-agent: billing-bot" \
  -H "Content-Type: application/json" \
  -d '{ "amount": 5000, "currency": "usd", "customer": "cus_123" }'

The request body here is the payload directly (no wrapping service/action/payload envelope; those are already in the path and headers). Response shape is identical to the webhook style above.

MCP

For Claude Desktop, Cursor, or any MCP client: every tool call through this gateway gets the same dedup, validation, rate-limiting, and audit logging as the REST routes.

{
  "mcpServers": {
    "agentraas": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://your-instance/mcp"]
    }
  }
}
POST /mcp

Standard JSON-RPC 2.0 over HTTP (tools/list, tools/call). Authenticate with the same x-agentraas-key header as SDK-style REST.

Idempotency & tracing

Optional headers accepted by both the webhook and SDK-style routes, useful once you're running agents in production and want to correlate calls with your own systems:

HeaderPurpose
x-agentraas-idempotency-keyYour own dedup key, if you want to control the dedup window's scope yourself instead of relying on the request body being byte-identical.
x-agentraas-run-idCorrelates every call from one agent "run" together in the audit trail.
x-agentraas-step-idIdentifies which step within a run this call was, for multi-step agent workflows.
x-agentraas-end-userSDK-style equivalent of the webhook body's end_user_id.
x-agentraas-resource-idSDK-style equivalent of the webhook body's resource_id.

Errors

Every error response is a flat JSON object with the same shape, regardless of route:

{ "error": "A human-readable message." }

Some errors add a machine-readable code field alongside error for cases worth branching on in your own code (e.g. EMAIL_NOT_VERIFIED), and a few add extra context fields (e.g. replayed: true on a deduplicated dead-letter replay). Check the specific status code first, code isn't present on every error.

StatusMeaning
401Missing or invalid API key.
402Monthly usage limit reached (Cloud only; self-hosted has no enforced limit on any tier).
403Authenticated, but not permitted for this org/action.
422Request validation failed. Check the message for which field.
429Rate limit exceeded. See Plans & limits.
502/503The upstream service (Stripe, Twilio, etc.) was unreachable or errored; AgentRaaS fails closed rather than silently succeeding un-deduplicated.

SDKs

Thin, dependency-light wrappers over the SDK-style REST routes above. Both work against Cloud or any self-hosted instance.

Python

pip install agentraas
import agentraas

client = agentraas.Client(
    agentraas_key="ar_live_...",
    org_id="acme-corp",
    agent_id="billing-bot",
    base_url="https://your-instance",
)

result = client.call("stripe", "charge.create", {"amount": 5000, "currency": "usd"})

TypeScript / JavaScript

Not on npm yet. Build it from src/sdk-js in the repo (npm install && npm run build) until the package is published.

import { Client } from "agentraas";

const client = new Client({
  agentraasKey: "ar_live_...",
  orgId: "acme-corp",
  agentId: "billing-bot",
  baseUrl: "https://your-instance",
});

const result = await client.call("stripe", "charge.create", { amount: 5000, currency: "usd" });

Both SDKs are MIT-licensed. Neither retries automatically: since AgentRaaS claims the dedup slot server-side before forwarding, your own retry logic (as aggressive as you want) is always safe to call again with the same payload.

Supported services

Curated, pre-configured integrations, no code required:

Stripe, Twilio, HubSpot, Calendly, Shopify, Zoho, Razorpay, WhatsApp, Zapier, Make, Adyen, Mollie, Airwallex, Xendit, PayPal, Salesforce, Slack, Klarna, Paystack, GoCardless, Opn Payments, plus the built-in mockpay for safe testing.

Need something not on this list? See Custom Actions below.

Custom Actions

Register any endpoint yourself from the Custom actions panel (any URL, any auth type) and it gets the same dedup, audit trail, and SSRF guarding (so it can't be pointed at your own internal infrastructure) as a curated service. Call it exactly like a built-in service, using its registered name as service.

Inbound webhooks Enterprise

For the reverse direction: a third party (e.g. WhatsApp) calling into your system. AgentRaaS verifies the provider's real signature (HMAC or ECDSA, whichever that provider uses) before forwarding the payload on to your own destination URL, so you get signature verification without implementing it per provider.

GET / POST /v1/inbound/:token

Manage receivers from the dashboard's Outage alerts panel, or via /api/v1/inbound-webhooks.

Self-hosting

Self-hosted AgentRaaS has no enforced monthly usage limit on any tier; it's your infrastructure. One Docker Compose service, no data leaving your control.

./install.sh

This generates fresh secrets, runs migrations, and starts the stack. Key environment variables (full reference in .env.example):

VariablePurpose
JWT_SECRETSigns dashboard sessions. Required; the server won't start without it.
CREDENTIALS_ENCRYPTION_KEYEncrypts stored service credentials at rest. Required, 32 bytes.
PUBLIC_URLUsed for email links and the Connect Agent webhook/MCP URLs. Set this to your real domain.
AGENT_RATE_LIMIT_PER_MINPer-key rate limit across webhook/SDK/MCP routes. Default 300.
LICENSE_TOKENUnlocks Team/Enterprise features on this deployment. Get it from your Cloud account's Account → Your license panel after subscribing. Missing/expired always falls back to Community rather than blocking startup.
SMTP_*Optional. Without it, password-reset links are logged server-side instead of emailed.

Billing always happens on AgentRaaS Cloud, even for a self-hosted instance: Paddle checkout and your subscription live there. Self-hosting doesn't need its own Paddle account; you just paste the license token it issues you into LICENSE_TOKEN.
